# 글 작성 체인 (`/write`)

주제 하나를 넣으면 4개 워드프레스에 나갈 글을 **생성 → 검증 → 초안 업로드**까지 하고,
사람이 초안을 본 뒤 4개를 한 번에 발행한다.

```
info.mindpang.com → good.mindpang.com → ss.keywordegg.com → hub.mindpang.com → 최종 공식 링크
```

글은 **역순**(hub → ss → good → info)으로 만든다. 앞에서 만들어진 주소가
다음 글의 버튼 링크가 되기 때문이다.

## 설정

`.env.local` 에 아래를 채운다(`.env.local.example` 참고).

```
ANTHROPIC_API_KEY=
WP_USER=mindpang
WP_PASS=
CHAIN_BRAND_BLOCKLIST=          # 제목·본문에 들어가면 안 되는 브랜드명, 쉼표 구분
```

`WP_APP_PASS_HUB` 같은 애플리케이션 비밀번호를 넣으면 쿠키+nonce 대신 Basic 인증을 쓴다.
**이쪽이 훨씬 안정적이니 4개 사이트에서 한 번 테스트해 보길 권한다.** nonce 방식은
테마가 바뀌면 파싱이 깨지고 WAF 에 막힐 수 있다.

템플릿은 이 저장소 밖이 아니라 한 단계 위, 사이트별 폴더에서 읽는다
(`../hub/template.md`, `../keywordegg-wp/template.md`, `../good/template.md`, `../info/template.md`).

## 구조

| 파일 | 역할 |
| --- | --- |
| `types.ts` | 잡·플랜·초안 타입. 화면에서도 쓰므로 node 의존성이 없다 |
| `config.ts` | 사이트 4개 설정, 템플릿 로딩, 환경변수 |
| `prompts.ts` | 단계별 프롬프트와 공통 규칙(`HOUSE_RULES`) |
| `llm.ts` | Anthropic 호출. 리서치 단계만 웹서치를 붙인다 |
| `validate.ts` | **규격 검사. 전부 결정론적 코드다** |
| `wp.ts` | 워드프레스 발행·상태변경·슬러그 확인 |
| `store.ts` | 잡 상태를 `.chain-jobs/*.json` 에 둔다 |
| `pipeline.ts` | 위를 엮은 6단계 파이프라인 |

## 파이프라인

| 단계 | 담당 | 하는 일 |
| --- | --- | --- |
| research | LLM + 웹서치 | 최종 링크 확보, 사실 카드 수집, **링크 헬스체크** |
| plan | LLM | 슬러그·제목·H2 구조·키워드 배치. **4개 사이트 슬러그 충돌 사전 확인** |
| generate | LLM ×4 | 템플릿을 통째로 프롬프트에 넣어 hub → ss → good → info 순 생성 |
| validate | **코드** | 규격 검사. 실패하면 위반 항목만 짚어 재생성(최대 3회) |
| drafting | 코드 | 4개 사이트에 `status: draft` 로 업로드 |
| publish | 코드 | 확인 후 일괄 publish → 실제 페이지를 긁어 링크·키워드 재확인 |

## 왜 검증을 코드로 하는가

`validate.ts` 는 전부 정규식이다. "H2 에 키워드 넣어줘" 라고 프롬프트에 써도 지켜지지 않는다.
사람이 쓴 글에서도 H2 6개 중 4개가 규격을 어긴 사례가 있었다.
생성 → 검사 → **위반 항목만** 피드백 → 재생성 루프가 이 기능의 핵심이다.

검증기가 헐거워지지 않았는지는 사람이 검수한 글로 확인한다.

```bash
npm run chain:selftest -- <검수한-글이-있는-폴더>
```

통과 케이스만 두면 "아무것도 안 잡는 검증기" 도 통과하므로,
규격을 어긴 글이 실제로 걸리는지도 함께 본다.

### 눈에 안 보이지만 깨지면 티가 나는 규칙

- **ss** — 하단 CTA 가 마지막 문단 **위**에 있어야 한다. 글이 버튼으로 끝나면 그 아래 자동광고가 붙는다.
- **ss** — 세로 스택 버튼 3개 사이에 줄바꿈이 없어야 한다. `wpautop` 이 `<br>` 을 끼워 넣는다.
- **info** — H2 **전부**에 핵심 키워드. 네이버 광고 키워드 관련성 판정에 쓰인다.
- **info** — 외부 링크 금지, 버튼 5곳 이상 전부 good 으로.
- **good** — H2·표·FAQ 금지, 본문 2문단 500자 내외. 버튼이 주인공이다.
- **hub** — 리서치에서 확인된 URL 외의 링크 금지.

## 사실 검증

자동화에서 제일 약한 고리다. 실제로 겪은 것들을 코드로 막아 뒀다.

- **HTTP 200 이 살아 있다는 뜻은 아니다.** gov.kr 페이지가 200 을 주면서 본문은
  "삭제승인요청 상태" 인 경우가 있었다. `DEAD_MARKERS` 로 본문까지 본다.
- 일부 기관 사이트는 curl 기본 UA 에 응답하지 않아 브라우저 UA 로 요청한다.
- 팩스번호·계좌번호는 정규식으로 차단한다. 틀린 팩스번호를 실으면 독자의 진단서가 남의 사무실로 간다.
- 금액·시간처럼 자주 바뀌는 값은 리서치가 `volatile: true` 로 표시하고,
  프롬프트가 "최신 안내 확인" 으로 유도하게 한다.

## 제약

- **로컬 전용.** 생성이 3~8분 걸리는데 API 응답 뒤에서 백그라운드로 돌기 때문에,
  프로세스가 살아 있는 `next dev` / `next start` 에서만 끝까지 간다.
  Cloudflare Workers 로 배포하면 응답이 끝나는 순간 잘리고, 템플릿을 읽는 `node:fs` 도 못 쓴다.
  배포까지 가려면 별도 워커 프로세스와 큐가 필요하다.
- 슬러그가 이미 있으면 잡이 실패한다. 기존 글 수정 모드는 아직 없다.
- `CHAIN_BRAND_BLOCKLIST` 는 비어 있다. 네이버에서 걸렸던 상표들을 채워야 한다.
